Data factories

Justice Data Platform and the data factories framework together enable a shift in how MOJ data is delivered and analysed.

A data factory ingests raw data, cleans and transforms it, and produces data products ready for analysis and reporting.

Each business area will be responsible for its own data factory. They’ll be supported by data engineers and architects from the Office of the CTO.

Data engineers ingest, clean and standardise raw data from source systems. They take care of cleaning, de-duplicating, running lookups and any other processing within that factory.

Analytics engineers transform that data into trusted products, applying business logic and context. The finished products can be made available on the Justice Data Platform.

This framework allows for clearer ownership, easier governance, and better, more consistent metadata.

Single source of truth

Data factories allow for a single source of truth for data from an operational system. There should be no need for multiple pipelines from one source.

We're implementing this as a data lake. This will allow us to manage a large collection of structured and semi-structured data, with no one schema.

Clearer ownership

Factories are run by data and analytical engineers with the right domain expertise. They're also best placed to manage access to their data products.

Teams will not need to cover multiple domains beyond their expertise or capacity. Processing tasks like data cleansing can be done in one place for multiple users.

Improved security

Each factory is a separate Amazon Web Services (AWS) account, which limits risk if an account is compromised.

Using AWS Lake Formation means we can implement granular permissions at the row and column level, making it easier to comply with data protection law.
