Roadmap

Things we're working on now

Project based data access

We're replacing our YAML-based model with structured, project-scoped permissions. Our users will be able to manage permissions on the platform, with no need for GitHub access.

Non data project permissions

We're extending the project-based access model to cover tooling, including AI. We'll have one consistent permissions model across the platform.

Microsoft Entra implementation

We're replacing GitHub as our provider, to align with MOJ standards.

Mandatory metadata

We're establishing the minimum metadata required to share data. This will help establish trust and allow for further governance integration.

AI gateway infrastructure

We're building the AI gateway on Justice Data Platform infrastructure. We're also getting it ready for IT health check. The gateway will enable access to a wide range of LLMs and AI tools through a single API.

Things we'll do next

AI gateway user interface

We'll have a user interface for the gateway. This will mean easier management and cost attribution.

End-to-end project-based access

We'll build out the remaining user journeys. This will include requesting, approving/denying, and revoking data access. This will reduce reliance on informal channels for access.

Analytics

We'll establish baseline metrics for platform use, access patterns and request flows. This will allow us to measure outcomes and prioritise development based on evidence.

Catalogue rebuild

We'll rebuild Find MOJ Data on a new tech stack. It will align to the MOJ tech-radar, on Justice Data Platform infrastructure.

Things we'll do later

Minimum viable platform

We'll build a minimum viable end-to-end data platform. We'll cover the core data journeys: ingest, transform, orchestrate and analyse.

Governance accounts

We want the platform to serve as the governance layer for MOJ federated data. It will be the place to manage cross-domain data sharing, access policy and compliance.

Governance by default

We want to give stewards and data owners visibility of how data is being used after access is granted. This will help move governance from a one-time gate to an ongoing practice.

Self-service data access

We'll enable users to discover, request and access data assets without engineering intervention. Roles, responsibilities and rules will be clear and consistent.

Responsible AI at scale

We want model governance, cost attribution and guardrails embedded into the platform.

Data quality

We'll put in place guardrails and tools to ensure data meets quality standards before it is shared.

Data retention

We'll ensure that data retention policies can be met automatically, within the platform.

Full service migration

We will migrate or refactor the remaining Analytical Platform capabilities. Users will have access to all current functionalities on the new platform.

Things we've done

User research and technical feasibility discovery on the new access and permissions model.
